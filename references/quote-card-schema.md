# 金句／内容摘抄卡数据结构

本模式只承载可逐字核对的原句或连续短段落。页数由可靠摘录数量决定，最终 HTML 只适配手机屏幕并占满手机视口。

## JSON 结构

```json
{
  "book": {
    "title": "书名",
    "author": "作者",
    "meta": "版本、月份或阅读批次，可选",
    "accent": "#9B4637，可选"
  },
  "quotes": [
    {
      "text": "逐字摘录的内容",
      "source": "作者 · 章节名",
      "locator": "纸书第 38 页／官方试读第 2 章／用户提供摘录",
      "url": "公开来源 URL，可选",
      "size": "auto"
    }
  ]
}
```

## 字段规则

- `book.title`、`book.author` 和至少一条 `quotes` 必填。
- `text` 必须是已核对原文，不允许放转述、总结、改写或推读内容。
- `source` 是卡片上方的短来源，建议使用“作者 · 篇名”或“章节名”。
- `locator` 是核对位置，必填；没有页码但来自用户材料时写“用户提供摘录，页码未提供”。
- `url` 可选，只用于公开网页来源。
- `size` 可填 `auto`、`xl`、`normal` 或 `sm`。默认 `auto`：短句使用大字号，长段落使用小字号。
- 摘录按原书出现顺序排列；按主题筛选时，也保持入选句子的原始顺序。

## 长度建议

- 28 个字符以内：适合 `xl`。
- 29–58 个字符：适合 `normal`。
- 59–160 个字符：适合 `sm`。
- 超过 160 个字符时，应判断能否在不改变原意的前提下选取一个完整连续片段；不能就拆成相邻两页，并在 `source` 中保留相同章节定位。

## 输出边界

- 不增加解读、成长场景、行动建议或口号。
- 不制造封面页；书名只出现在固定顶部栏。
- 每屏只出现一条摘录。
- 不设置固定卡片数量。
